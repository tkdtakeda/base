Tauri + Rust + HTML/CSS/JavaScriptを使用し、対象データを検索するデスクトップアプリケーションを作成してください。

【前提】
・外部AIへ提供している情報は匿名化済みです。
・実際の共有パス、DB名、テーブル名、列名、実データは提供しません。
・config.sample.jsonと同じ構造を持つconfig.local.jsonを実行環境で読み込みます。
・ソースコードへ物理DB情報を直接記述しないでください。
・山括弧で囲まれた値はプレースホルダーです。実在する値として扱わず、設定値として読み込んでください。

【必須構成】
・フロントエンド: HTML / CSS / JavaScript
・デスクトップ基盤: Tauri
・ネイティブ処理: Rust
・データベース: SQLite
・初期版ではPythonを使用しない

【データアクセス】
・SQLiteへの接続とSQL実行はRust側だけで行う
・HTMLおよびJavaScriptからSQLを直接実行しない
・共有SQLiteは読み取り専用として扱う
・共有SQLiteを一時ファイルへコピーする
・コピー完了後にSQLiteとして開けることを確認する
・必要なテーブルと列の存在を確認する
・検証成功時だけ現行キャッシュと置換する
・検証失敗時は直前の正常キャッシュを維持する
・アプリケーションはローカルキャッシュを検索する

【論理検索項目】
・lotNo
・inspectionNo
・castingNo
・orderNo

【論理表示項目】
・lotNo
・inspectionNo
・castingNo
・orderNo
・material
・temper
・size
・customer
・deliveryDate
・process
・equipment
・status

【必要なTauri Command】
・search_lots
・get_lot_detail
・refresh_cache
・get_cache_status
・get_application_info

【UI要件】
・検索種別選択
・検索文字列入力
・検索実行
・検索結果一覧
・選択行の詳細表示
・キャッシュ更新ボタン
・キャッシュ状態表示
・0件表示
・利用者向けエラー表示

【安全要件】
・SQLは必ずパラメーター化する
・検索値をSQL文字列へ直接連結しない
・フロントエンドから任意のSQL、物理列名、物理テーブル名、ファイルパスを指定できないようにする
・ログへ認証情報や検索結果全文を出力しない
・Rust内部エラーを画面へそのまま表示しない

【テスト要件】
・ダミーSQLiteでテストできること
・共有元へ接続できないケース
・破損したコピーのケース
・必要テーブルが存在しないケース
・必要列が存在しないケース
・検索結果0件のケース
・日本語や記号を含む検索値のケース
